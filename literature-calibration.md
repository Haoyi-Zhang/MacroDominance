# Full-paper calibration matrix

This matrix records the required non-overlapping 12+5+5 calibration set. “Complete” means the full paper or a corresponding author manuscript was inspected for its problem, principle, argument, practical connection, evaluation, artifact, narrative, section structure, bibliography scale, and visual evidence. It does not mean every cited work in the manuscript was read in full, nor does it establish novelty by itself. Scholarly PDFs are not redistributed.

## Five demonstrably influential/foundational papers

| Key | Problem and principle | Argument, practice, evaluation, artifact | Narrative / bibliography / visuals | Delta to this work |
|---|---|---|---|---|
| `dechter1999` | unify exact reasoning tasks through variable elimination; **principle:** bucket elimination orders functions and combines/eliminates variables locally | correctness by distributive elimination; complexity governed by induced width; **practice:** CSP, probabilistic inference, optimization and diagnosis; **evaluation:** multiple canonical problem families and complexity comparisons; **artifact:** conceptual algorithmic framework; no single software artifact central | unification motivation -> generic algorithm -> instantiations -> complexity -> discussion; generic framework followed by domain specializations; 100+ refs; bucket/order graphs and complexity tables explain genericity | establishes generic elimination; does not identify the HPWL self-context maximizer or coverage certificate |
| `aji2000` | explain many message-passing algorithms as one distributive computation; **principle:** generalized distributive law on commutative semirings over junction trees | algebraic correctness and complexity conditions plus worked applications; **practice:** decoding, transforms, dynamic programming and inference; **evaluation:** diverse algebraic examples rather than physical-design benchmarks; **artifact:** theoretical framework; no artifact expected | algebra -> junction tree -> scheduling -> applications -> complexity; theorems, examples, application sections; ≈55 refs; junction-tree/message diagrams and operation-count tables are central | gives the algebraic umbrella; this work contributes a geometry-specific message quotient and checker |
| `factorgraphs2001` | represent factorization and derive local sum-product computation; **principle:** factor graphs expose variables/functions and pass messages on edges | derivation exact on cycle-free graphs; approximate/iterative behavior on cycles; **practice:** coding, signal processing, inference and state-space models; **evaluation:** many worked algorithms and examples; no benchmark campaign; **artifact:** tutorial/theoretical artifact rather than software | representation -> sum-product derivation -> examples -> cycles -> applications; tutorial sections with repeated algorithm instantiations; ≈65 refs; factor-graph diagrams are the primary explanatory device | generic message passing does not prove which placement response parameters are sufficient |
| `necula1997` | execute untrusted code safely without trusting a complex producer; **principle:** producer supplies a proof; consumer validates it against a safety policy | formal safety argument and prototype feasibility; **practice:** mobile/untrusted machine code with small trusted checker; **evaluation:** prototype proof generation/checking examples and overhead; **artifact:** prototype architecture; foundational trust-separation pattern | threat model -> proof-carrying architecture -> logic/checker -> implementation -> results; policy/logic, proof generation, prototype evaluation; ≈30 refs; architecture/proof diagrams and overhead tables carry the argument | inspires producer/checker separation; our certificates are domain-specific coverage witnesses, not machine-code proofs |
| `certifying2011` | reduce trust in sophisticated algorithms by returning checkable witnesses; **principle:** certifying algorithm emits output plus certificate checked by a simple verifier | domain-by-domain correctness arguments and checker design principles; **practice:** graph, geometry, numerical and combinatorial software; **evaluation:** broad survey with implemented examples and failure modes; **artifact:** LEDAs/certifying-software lineage; multiple implementations discussed | motivation -> principles -> examples by domain -> engineering guidance -> outlook; survey taxonomy plus detailed exemplars; ≈150 refs; certificate diagrams and example tables compare witness/checker patterns | sets the certification standard; this work supplies one exact placement-specific certificate contract |
